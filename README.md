# Landslide recurrence analyses in Far-Western Nepal

This repository contains the Python code used for the analyses in **“Persistent susceptibility and short-lag history dependence in recurrent landsliding in Far-Western Nepal Himalayas.”**

The workflow builds annual slope-unit landslide histories, fits the recurrence and rainfall–history models, runs the temporal and spatial randomizations, evaluates expanding-window prediction, and generates the manuscript figures and machine-readable supplementary outputs.

The repository starts from analysis-ready inputs. It does not reproduce the upstream GIS and remote-sensing preprocessing from the original raw datasets.

## Requirements

Python 3.11 is recommended. Install the required packages in a clean environment:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

On Windows PowerShell, activate the environment with:

```powershell
.venv\Scripts\Activate.ps1
```

## Input data

The analysis-ready data are distributed separately as a Zenodo data archive. After downloading the data package, place the seven required input items directly in the `input/` directory. File names, required fields, aliases, and data checks are described in [`input/README.md`](input/README.md).

## Running the workflow

Validate the input files first:

```bash
python run_all.py --config config.yaml --stage validate
```

A short installation test can then be run with:

```bash
python run_all.py --config config.yaml --stage all --quick
```

Quick mode uses 99 randomizations and two prediction years. It is intended only to check installation and file compatibility.

Run the complete analysis with:

```bash
python run_all.py --config config.yaml --stage all
```

The full workflow runs the following stages:

1. input validation;
2. history construction;
3. recurrence modelling;
4. rainfall–history modelling;
5. expanding-window prediction;
6. fixed-margin temporal randomization;
7. spatial chronology randomization;
8. publication-output audit;
9. figure generation; and
10. supplementary-file assembly.

Individual stages can also be run separately, for example:

```bash
python run_all.py --config config.yaml --stage history
python run_all.py --config config.yaml --stage prediction
```

Stages that use the reconstructed history panel require the history stage to have been run first. If the inputs or configuration are changed, use a new `output/` directory or remove the previous one before rerunning the workflow.

## Figures and supplementary tables

The complete workflow generates the manuscript figures and machine-readable supplementary files. Figures can be regenerated from completed output tables with:

```bash
python make_figures.py --config config.yaml
```

The formatted supplementary tables can be generated with:

```bash
python build_supplementary_tables.py
```

## Reproducibility outputs

Each run writes `output/run_manifest.json`, which records input hashes, code hashes, the configuration hash, and the detected software environment. Input validation and publication-output checks are written under `output/audit/`.

The numerical values reported in the manuscript should be taken from one complete run using the same code, configuration, and analysis-ready data archive.
